## 1.1 Staged gate protocol — pre-registered criteria for any engine edit

Owner decision 2026-08-01. This replaces the Q11 freeze: engine edits are allowed, but an edit is not "verified" until it has paid the gates below. **The criteria here are pre-registered — they are fixed before a gate runs, so a result cannot be re-interpreted as "borderline" after the fact.** Changing a threshold is allowed; changing it *after seeing the run it would judge* is not, and any such change must be dated and recorded in this section.

| Gate | What runs | Cost | Proceed only if |
|------|-----------|------|-----------------|
| **0** | `npm run lint`, `npx tsc --noEmit`, `npm run build`, `eval:hinge-check`, `eval:collision-check` + `eval:input-integrity` re-scored on stored runs | **$0** | all green, and the offline re-scores match their last recorded values. **`build` is required only when the diff touches the Next build graph — amendment adopted 2026-08-02, see the table below; an eval-only diff records "build not run" rather than counting as green** |
| **1** | `eval:baseline` 5 fixtures on the edited code **+ a control arm on the pre-edit code in the same session** | ~$0.90 ×2 | no Gate-1 trigger fired (table below) |
| **2** | `eval:stability` ×1 (20 analyses) | ~$3.60 | no Gate-2 trigger fired |
| **3** | `eval:stability` ×2 (20 analyses) | ~$3.60 | **run only when a Gate-2 trigger fires** — see the revert rule |

**Triggers — any one of these stops the edit and escalates.**

| # | Trigger | Gate | Why it is on the list |
|---|---------|------|----------------------|
| T1 | `hard_fail > 0` on any fixture | 1 | a hard assertion is a contract, not a distribution — one occurrence is actionable with no replicate needed |
| T2 | `shift > 0` anywhere | 1, 2 | frame escape: the hinge left the fixture's declared `expected_spof_themes` |
| T3 | A fixture that was `same` in the **two prior** baselines returns `swap` | 2 | the only per-fixture stability signal that has ever actually moved |
| T4 | ≥2 fixtures change hinge theme category in the same run | 1, 2 | broad simultaneous movement is not plausible run-to-run noise |
| T5 | Any band moves ≥2 steps (e.g. `Medium → Very High`), or `likelihood` moves at all. **Adequacy-ceiling exemption, adopted 2026-08-02, applies to runs from 2026-08-02 onward only:** a `spof_confidence` move is exempt when *both* hold on disk in the same comparison — the variant's `meta.input_adequacy.score` is **lower** than the original's, and the variant carries a `Confidence lowered from … to … because …` warning (`src/lib/confidence-ceiling.ts`, surfaced in `summary.json` `warnings[]` and per-side `adequacy`). Nothing else is exempt: `likelihood` moving at all still fires, and a confidence move with equal-or-higher adequacy still fires | 1, 2 | single-step band drift is measured noise; two steps and likelihood are not. The exemption exists because `para`/`strip` variants are *built* thinner, so the E20 ceiling — the engine working as designed — would otherwise fire T5 on most stability runs and make the trigger meaningless. It is written as two on-disk field checks, not a judgement call, so it cannot become an escape hatch |
| T6 | Soft-fail count rises above the control arm's by ≥3 across the 5 fixtures | 1 | a style/content contract loosening in bulk |

**T2 alone is not a sufficient gate, which is why T1/T3–T6 exist.** After Q20 re-scored all 109 stored sides, `shift` is **0 everywhere on disk** — the trigger has never legitimately fired, so an edit that passes only "shift = 0" has passed a test that passes in nearly every world, good or bad. What has demonstrably moved in this corpus is `swap` (9 co-valid), hinge oscillation on ≥3 of 5 fixtures, single-step band drift, and assertion counts. Gate on those.

**Control-arm rule (the one that costs money and is worth it).** Gate 1 compares against a control measured **in the same session**, not against a stored baseline from another day or another pipeline state. Reason on record: on 2026-08-01 the same fixture, model and day gave `confidence` id = `Very High` 3/3 when the locales were run in separate batches and 1/3 when they were paired inside one run (see the Q16 paired-run note). If a batch window minutes wide can move a band, a cross-day baseline cannot be the control for a prompt edit. Stored baselines stay useful as trend context — never as the comparison that decides a revert.

**Revert rule.** Revert only on **repeatable** evidence. So a Gate-2 trigger does not authorise a revert by itself — it forces Gate 3, and the revert happens if Gate 3 reproduces the trigger. Corollary to budget honestly: the ~$3.60 saved by skipping Gate 3 only materialises in the clean branch; a dirty Gate 2 costs the full ~$8.10.

**Piggyback rule.** Gate 2's 20 analyses are also the corpus **K2** needs (its stated verification is N1 + N2 over `eval/golden/*.json`, i.e. stability + collision). Collision / false-specificity scoring re-reads stored output and is **free** — Q17 re-ran on baseline `2026-08-01_005921` at $0. So any Gate 2 run must be scored for K2 as well before its raw dumps age out: one payment, two answers.

**Recording rule.** Every gate run's `run_id`, triggers checked, and verdict go into a run note under §1 — including the runs that passed. A gate whose failures are recorded and whose passes are not is not a measurement.
